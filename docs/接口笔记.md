# Luker 原生迭代工作室接口笔记（工作台复用用）

路径前缀：`S = /scripts`（对应 `public/scripts`）。同 URL 动态 import 拿到的是同一个模块实例，不会重复跑副作用。

## 0. 复用度总表

| 工作室 | live 构建 | tools | edit 转换 / apply | commit | prompts |
|---|---|---|---|---|---|
| A MG schema | 可直接用 | 可直接用（再加 1 个内联 read 工具） | 需要适配：path:'' 整体替换 | 可直接用 | 可直接用 |
| B Orchestrator | 需要适配（preset-library 已导出） | 用不了（未导出） | 用不了（executor 未导出） | 需要适配 | 用不了（未导出，只能读 settings 里的字符串） |
| C CPA | 可直接用（`ctx.presets`） | 可直接用 | 可直接用（`applyEdits`） | 可直接用 | 可直接用 |
| D CEA | 可直接用 | 可直接用 | 需要适配（rebase + 按目标分组） | 可直接用 | 可直接用 |

四个工作室共用的部分：
- 运行器：`S/iteration-library/index.js` → `runner.requestToolCallsWithRetry`，也可以从 `Luker.getContext().iterationLibrary.runner` 拿到（index.js:1-8）。
- edit 引擎：`applyEdits(edits, live) → {newLive, clean, conflicts, alreadyDone}`（lib/edits/types.d.ts:4-35）。op 有 `set{path,oldValue,newValue}`、`str_replace{path,find,replace,expected_count}`、`str_insert`、`str_delete`、`list_insert/remove/move`、`unset`，CEA 另外注册了 `lorebook_entry_add/update/remove`（character-editor-assistant/index.js）。注意：`set` 配 `path:''` 时 lodash 不会生效，要自己做整体替换。
- edit 结果包络：`buildEditToolResultPayload('pending'|'committed'|'rejected'|'conflict')`（iteration-library/edit-tool-result-envelope.js:53）。
- 世界书只读工具：`tools.lorebookReads.{LOREBOOK_READ_TOOL_DEFS, isLorebookReadTool, runLorebookReadTool(call,{context,avatar})}`，工具名有 `world_book_list/lorebook_list/lorebook_query/lorebook_get`，返回 `{ok,result}|{ok:false,error}`（tools/lorebook-reads.js:33-49,249）。
- 按路径读字段：`readFieldsByPaths(root, paths)`（iteration-library/read-fields-helper.js:98）。

## 7. 单轮运行器（四个工作室一致）

`requestToolCallsWithRetry(context, {toolCallRetryMax, rpmLimit}, opts)`（lib/iter-tool-calling.js:170）
- opts 字段：`taskMessages, runtimeWorldInfo:null, apiPresetName, llmPresetName, tools(必填且非空), abortSignal, includeAssistantText:true, allowNoToolCalls:true, isControlCall, onAssistantText, onToolCall, onControlCall, onUsage, allowedNames, substituteMacros(默认 false)`。
- 底层走的是 `context.generateTask({includeCharacterCard:true, worldInfoSource:'none', toolChoice:'auto', ...})`（:217-239）。如果 llmPreset 开了 stream，会改走 `generateTaskStream`。`apiPresetName` = 连接配置名，`llmPresetName` = CC 预设名，后者决定提示词外壳（generate-task.js:317-350）。
- 返回 `{toolCalls:[{id,name,args,raw}], assistantText, reasoning, reasoningBlocks, reasoningDetails}`。没有工具调用、也没有文本时会抛错，然后按 retries 重试。
- 工具结果怎么回填：assistant 消息写成 `{role:'assistant', content, tool_calls:[{id,type:'function',function:{name,arguments:JSON}}], reasoning?}`，后面每个 call 跟一条 `{role:'tool', tool_call_id, content:string}`。read 工具填真实结果，edit 工具先填 `proposal_pending` 包络，等用户操作后原地改写（MG studio.js:1716-1795）。
- 轮次：没有硬上限。只要上一轮有任意工具调用就继续，而且必须满足 `!bus.hasOutstanding()`，也就是没有待审 edit（MG studio.js:2393-2399）。CEA 的条件是有 pendingEdits 就停，没有工具调用也停（CEA studio.js:966-968）。
- 首条消息：MG、Orch、CEA 直接发用户原文。CPA 会把最后一条 user 改写成增强格式（见 C.6）。

## A. Memory Graph schema（memory-graph/schema-iteration）

1. live：`getEffectiveNodeTypeSchema(ctx, settings)`（memory-graph/character-overrides.js:137），返回规整后的 schema 数组。有角色 override 就用 override，否则用全局 `settings.nodeTypeSchema`。规整函数是 `normalizeNodeTypeSchema`（main.js:620）。`settings = extension_settings.memory_graph`。
   - 作用域：`getSchemaScopeInfo(ctx, settings) → {avatar, hasAvatar, characterName, hasOverride, scope, schema}`（character-overrides.js:148）。工作室的规则是只要选了角色就算 character 作用域（studio.js:1170-1185）。这些函数也通过 `ctx.getExtensionApi('memory-graph')` 暴露（memory-graph/api.js:118）。
2. tools：`buildToolCatalog()`（tools.js:238），包含编辑工具 `mg_schema_set_node_type / mg_schema_remove_node_type / mg_schema_reorder_node_types`，以及控制工具 `CONTROL_TOOL_NAMES.resetToBlank='luker_mg_schema_reset_live_to_blank'`、`resetToGlobal='luker_mg_schema_reset_live_to_global'`（tools.js:42），判断函数是 `isMgSchemaControlCall`。只读工具 `mg_schema_read_fields` 只在 studio.js:116 内部定义，没有导出，需要自己抄一份定义，执行用 `dispatchMgSchemaReadFields({liveSchema, args})`（read-fields-dispatcher.js:48）。character 作用域下工作室还会追加 `LOREBOOK_READ_TOOL_DEFS`。
3. tool→edit：`normalizeToolCallToEdit({function:{name, arguments:JSONstr}}, {live, normalizeNodeTypeSchema})`（tools.js:369），返回 `[{op:'set', path:'', oldValue, newValue}]`，空数组表示 noop，参数非法会抛错。同一轮有多个 call 时，要把上一条的 `newValue` 当成下一条的 `live` 传进去（studio.js:1987-2008）。
4. apply：不要用 `applyEdits`，取最后一条 edit 的 `newValue` 就是累计后的结果。工作室内部的 `applyEmptyPathSet`（studio.js:444）没有导出。
5. commit：character 作用域调 `persistCharacterSchemaOverride(ctx, avatar, normalized)`（character-overrides.js:190，内部走 `writeExtensionField`）；global 作用域写 `settings.nodeTypeSchema = normalized` 然后 `saveSettings()`（studio.js:1246-1260）。MG 设置面板的 UI 不会自动刷新，`refreshRootUi` 是 main.js 传进来的闭包。
6. prompt：`DEFAULT_SCHEMA_ITER_SYSTEM_PROMPT` / `buildSystemPrompt()`（system-prompt.js:25,92），英文。实际使用的是 `settings.schemaIterSystemPrompt || 默认值`，character 作用域下会再追加一段 "# Iteration scope" 提示（studio.js:1208，未导出）。额外指令直接拼在 system 后面就行。
8. 连接：`extension_settings.memory_graph.requestApiPresetName / requestLlmPresetName / toolCallRetryMax / rpmLimit`（main.js:442）。

## B. Orchestrator（orchestrator/iter-studio）

工作室依赖的核心函数都在 orchestrator/main.js 里，而且没有 export：`buildAiIterationToolSet`（:3393）、`buildAiIterationSystemPrompt`（:3244）、`executeAiIterationToolCalls`（:5747）、`applyAiIterationSessionToGlobal/Character`（:6236/:6324）。只能通过 `openOrchestratorIterationStudio(deps)` 的 deps 注入拿到，而 deps 是在 main.js:6568 内部组装的。所以工具执行这部分不能复用。

1. live：`getActivePreset(settings, mode, {scope, context, avatar}) → {ok, state}`（preset-library.js:343，已导出），然后用对应 mode 的规整函数：`sanitizeLoopProfile`（persistence.js:560）、`sanitizeAgendaWorkingProfile`（agenda-profile.js:84）、`sanitizeDirectorProfile`（director-defaults.js:711）。spec 模式不需要规整。`settings = extension_settings.orchestrator`，mode 用 `getExecutionMode(settings)`（character-overrides.js:65），工作台只支持 loop、agenda、director，其余都按 spec 处理。
   - 作用域：`getIterationDefaultScope(ctx)`（editor-display.js:56），有当前 avatar 就是 'character'。character 作用域没有 preset 时回退到 global。角色容器在 `character.data.extensions.orchestrator.presetLibraries/activePresetIds`（preset-library.js:113-138）。
2. tools：拿不到。只能读 `S/iteration-library/tools/` 下的共享工具（lorebook 读写、`characterPresetsReads.inspect_bound_preset`、`skillIterStudio`）。Orch 的编辑工具需要工作台自己实现，比如通用的 `set/str_replace` 按路径作用到 profile 上。
3/4. 原逻辑是在沙箱里调 executor，再 diff 出 `set('', after)`（studio.js:2326-2360）。替代做法：自己定义 path 型工具，然后用 `applyEdits` 作用到 profile 上。
5. commit：global 用 `writeActivePreset(settings, mode, 'global', payload)`（preset-library.js:405）或 `writePresetByName(...)`（:444），然后调 `ctx.saveSettingsDebounced()`。character 用 `persistCharacterLoopEditor/AgendaEditor/DirectorEditor/Editor(ctx, settings, avatar, {editor: profile})`（editor-persist.js:170-276，已导出，走 writeExtensionField）。原生 apply 还会刷新 Orch 面板（`renderDynamicPanels`）、改 `settings.executionMode`、弹出自定义工具的确认框，这些工作台都做不了，面板要等重新打开才会刷新。
6. prompt：不可调用。可以直接读 `settings.requestSystemPrompt` 和 `settings.iterModePromptLoop/Agenda/Director/Spec`。默认的 mode block 已导出：`DEFAULT_LOOP/DIRECTOR/AGENDA/SPEC_ITERATION_MODE_BLOCK`（main.js:2933-3184），英文。
8. 连接：`extension_settings.orchestrator.requestApiPresetName / requestLlmPresetName / toolCallRetryMax / rpmLimit`（studio.js:2600）。

## C. Completion Preset Assistant（cpa-iteration）

1. live：`ctx.presets.getStored(ref)?.body`，再经过 `ctx.openai.stripPresetConnectionFields(body)` 去掉连接字段（studio.js:935-939）。ref 是 `{collection:'openai', name, origin?}`；当前选中的预设用 `ctx.presets.getSelected('openai')`（cpa main.js:366）。参考预设同样用 getStored 读。
2. tools：`buildToolCatalog({hasReference})`（tools.js:496），会附带 skill 工具。编辑工具集合是 `EDITABLE_TOOL_NAMES`（:150，共 15 个，如 `preset_set_field/str_replace(_in_prompt)/upsert_prompt_entry/...`）。只读工具集合是 `READ_TOOL_NAMES`（:221）：`preset_read_live_fields / preset_read_reference_fields / preset_diff_reference / preset_simulate / preset_clone_to_new`，其中最后一个有副作用。控制工具为空，`isCpaControlCall` 恒为 false。skill 工具用 `isCpaSkillTool` + `runCpaSkillTool(call)`（:107,135）判断和执行。
3. read：`runCpaReadTool({id,name,args}, {live, reference, referenceName, presetName, context, cloneAndSwitchTarget?, checkPresetNameAvailable?})`（tools.js:898）→ `{ok,result,toolResultText?}`。edit：`normalizeToolCallToEdit({function:{name,arguments}}, {live, session, getReferencePresetBody})`（:1281），返回标准 Edit[]，比如 `{op:'set', path, oldValue, newValue}`。
4. apply：`applyEdits(edits, structuredClone(live)).newLive`。多个 call 时逐个链式推进 live（studio.js:2054-2090）。
5. commit：`await ctx.presets.save(ref, live, {select:true})`（studio.js:1189-1193）。内部走 `persistPreset` 加 `manager.updateList`，UI 下拉和设置会刷新（st-context.js:1106-1157）。
6. prompt：`buildModelSystemPrompt({mode})`（system-prompts.js:638，mode 取值 `general|orchestrator-optimize|jailbreak-only`），英文。实际使用 `settings.iterBaseSystemPrompt` 加 mode block（studio.js:1681-1688）。最后一条 user 的格式是：`Target preset: <name>\n\nSelected reference preset: …\n\n[skills block]\n\nUser request:\n<text>`（studio.js:1508-1528），skills block 由 `buildCpaSkillsBlock`（skill-prompt.js:139）生成。
8. 连接：`extension_settings.completion_preset_assistant.requestLlmPresetName / requestApiPresetName / toolCallRetryMax / includeWorldInfo`（cpa main.js:36）。

## D. Character Editor Assistant（editor-iteration）

1. live：`buildUnifiedCharacterEditorLiveSnapshot(ctx, avatar)` → `{character, lorebooks:{[book]:{entries,...}}}`（cea main.js:3023，已导出）。只预加载主世界书 `character.data.extensions.world`。如果要改别的书，需要自己 `ctx.loadWorldInfo(name)` 然后放进 `lorebooks[name]`。不支持群聊（main.js:1202）。
2. tools：`buildCeaEditorToolSet(ctx, settings, {live, hasSearchTools})`（tools.js:692）。编辑工具：`cea_set_card_field / cea_str_replace_card_field / cea_add_lorebook_entry / cea_update_lorebook_entry / cea_str_replace_lorebook_entry_field / cea_remove_lorebook_entry / cea_set_lorebook_metadata`。只读工具：`cea_read_card_fields / lorebook_list / lorebook_query / lorebook_get / world_book_list / simulate_prompt / inspect_bound_preset / web_search`，用 `isCeaEditorReadTool` 判断。控制工具为空。
3. read：`runCeaEditorReadTool({id,name,args}, {context, settings, helperApis, state})`（tools.js:826）。`cea_read_card_fields` 只需要 `state.live.character`，不依赖 helperApis。其他只读工具会映射到旧名 `luker_card_*`，交给 `helperApis` 执行。
   - `helperApis` 由 `buildCharacterEditorHelperApis(ctx, {avatar})`（main.js:2991，已导出）生成，是一个数组，元素形如 `{isToolName(name), invoke(call), toolNames?}`，包括 lorebook、lorebookWrite、simulate、worldBookList、boundPreset，还有可选的 search（`Luker.searchTools`）。外部直接调用这个函数就能拿到。另一种做法是世界书读取改用共享的 `runLorebookReadTool`，不需要 helperApis。
   - edit：`normalizeToolCallToEdit({id,name,args}, {context, live})`（tools.js:725）。返回的 edit 带 `target:{kind:'character'}` 或 `target:{kind:'lorebook', bookName}`，路径是 `card.<field>` 或 `lorebook.entries` / `lorebook.<meta>`。锚点没找到会抛错，错误对象带 `err.envelope`。
4. apply：先按 `target` 分组，再把路径前缀 `card.` / `lorebook.` 去掉（studio.js:1103,1179，未导出，需要自己复刻，大约 20 行），然后对 `live.character` 和 `live.lorebooks[book]` 分别调 `applyEdits` 做预览。
5. commit：
   - 角色：`commitCharacterEditorOperations(ctx, avatar, charEdits, {liveCharacter})`（main.js:1357），内部走 `mergeCharacterAttributes` → `updateCharacterData` / `writeExtensionField`。
   - 世界书：`commitLorebookOperations(bookName, liveBook, bookEdits, {context, settings})`（main.js:1446），内部走 `ctx.saveWorldInfo`。
   - 两者都返回 `{applied, conflicts, alreadyDone, persisted}`，不会主动刷新角色面板。
6. prompt：`DEFAULT_SYSTEM_PROMPT`（editor-iteration/studio.js:756，已导出），英文。实际使用 `settings.editorIterationSystemPrompt`。首条消息就是用户原文，可以选择用 `seedSystemMessage` 先插一条 system（`_internalSeedSystemMessage`，:383）。
8. 连接：`extension_settings.character_editor_assistant.requestApiPresetName / requestLlmPresetName / toolCallRetryMax`（main.js:82）。
- `studio/`（CardApp Studio）是另一套文件编辑器，入口 `sendAIMessage(charId, msgs, userMsg, opts)`（studio/ai-chat.js:2418），和这次的四个目标无关。

## 9. ctx.presets（st-context.js:2561）

- ref 形状：`{collection:'openai', name, origin:{kind:'global'} | {kind:'character', avatar}}`。`resolve(target)` 会把它规范成规范名（:868）。
- `list('openai')` → ref[]，包括当前角色卡绑定的预设和全局预设（:935）。
- `getSelected('openai')` → 当前 CC 预设的 ref（:970）。`getLive('openai')` → 当前 UI 里的 body，可能是未保存的状态（:995）。
- `getStored(ref)` → `{ref, body, source, selected, stored}` 或 null（:1056）。
- `save(ref, body, {select?})` → `{ok, ref, mode, body, snapshot}`（:1106）。保存角色卡绑定预设时会走 `updateCharacterBoundPreset`。

## 10. itemizedParams（itemized-prompts.js:183）

- 签名 `itemizedParams(itemizedPrompts, promptSetIndex, mesId)`。第二个参数是数组下标，不是 mesId。下标用 `findItemizedPromptSet(itemizedPrompts, mesId)`（:350）找，这个函数会打印大量 console.log。也可以自己 `itemizedPrompts.findIndex(x => x.mesId === ctx.chat.length - 1)`。`itemizedPrompts` 是模块级的 `export let`，需要 import `S/itemized-prompts.js` 读 live binding，ctx 上没有。
- 公共字段（每次都会 tokenize 14 段文本）：`charDescriptionTokens, charPersonalityTokens, scenarioTextTokens, userPersonaStringTokens, worldInfoStringTokens, allAnchorsTokens, authorsNoteStringTokens, smartContextStringTokens, beforeScenarioAnchorTokens, afterScenarioAnchorTokens, zeroDepthAnchorTokens, chatInjects, chatVectorsStringTokens, dataBankVectorsStringTokens, thisPrompt_padding, this_main_api, modelUsed, apiUsed, presetName, messagesCount, examplesCount`。
- CC 模式（`this_main_api=='openai'`，:255-298）：`oaiMainTokens, oaiStartTokens, ActualChatHistoryTokens, examplesStringTokens, oaiPromptTokens, oaiBiasTokens, oaiJailbreakTokens, oaiNudgeTokens, oaiImpersonateTokens, oaiNsfwTokens, finalPromptTokens, thisPrompt_max_context, oaiSystemTokens`，以及 `*Percentage` 系列和 `selectedTokenizer`。
- 开销：`getTokenCountsAsync` → `/api/tokenizers/openai/count-batch`，按 `model-hash` 走 tokenCache 缓存（tokenizers.js:1086-1106），所以重复调用基本命中缓存。不过 oai* 字段本来就是生成时预先算好、存在 promptSet 里的（script.js:10276-10287），如果只要这些分段数，直接读 `itemizedPrompts[i].oai*Tokens` 就行，完全不需要 tokenize。
